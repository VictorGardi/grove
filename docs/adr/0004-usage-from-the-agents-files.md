# The usage panel reads the agents' files at every start and keeps no record

Supersedes [ADR 0003](0003-usage-history.md). The usage panel shows only what the agents' own files still contain. The core builds the usage history in memory from the readers at every start, in small slices so the loop never stalls and with the "still building" progress as before. Nothing is written to disk: no history file, no saved reader positions, no copies set aside, no wipe.

Why: the saved record was rewritten in full on every save. On a history of hundreds of thousands of requests that was up to gigabytes of disk churn per hour, and keeping it safe (a temp file renamed over, slices, a sweep of what a kill left behind, copies of an unreadable file, a wipe that had to beat a save under way) was most of the usage code. The price of ADR 0003 was a record that grows without bound and names the user's folders.

What is lost, and accepted: days an agent prunes. Terminal Claude keeps about 30 days by default; Claude Desktop and Copilot keep what they keep, as long as their files exist. When an agent prunes, the matrix is shorter after the next start, and a day older than the earliest request the files hold is drawn as "no record that far back", not as zero activity. The panel no longer says "history from <date>".

Kept from ADR 0003, because it is about how agents write their records and not about saving them: one entry per request, keyed, so a later and larger count replaces a partial one and a resumed session's copy is not counted twice; the local day derived from the timestamp; Claude Desktop as its own slice; Copilot via OpenCode counted once under Copilot; credits apart from requests; an agent shown only if it made a request in the last 30 days. Incremental reading stays while the core runs: each reader keeps its byte offsets (and OpenCode its row positions) in memory and tails what the agents add, so the 5 s refresh stays cheap.

Also kept: the list of requests tagged "not tracked by Grove" before Grove's own record of the session could have arrived. A session that starts while the core runs may write requests before its per-tab record is read, and the offsets have already moved past them, so the next refresh of Grove's records re-tags them as Grove's. A new start reads everything with the records as they are then, so it needs no such list for what it reads first; the list is only for the core that keeps running. What Grove learnt from its per-tab files (which sessions it ran, since when) is likewise learnt again at each start and no longer saved, so a per-tab file that was deleted stops counting after a restart: its requests read as "can't tell" or "not tracked".

Consequences: a start reads every file again (about 6 to 14 s of Claude transcripts on the author's machine, in slices, with the panel saying it is still building). Nothing about usage is left on disk, so there is nothing to wipe, set aside or protect; the file an earlier build wrote (`usage-history.json`, its temp files and its `.corrupt-*` copies) is deleted when the core starts, since it names folders. A search across past conversations still needs its own decision (ADR 0002).
