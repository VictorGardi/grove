The downgrade, reported once at the moment it happens — an AppShell banner, which grove already has and already threads for service errors (App.tsx:138).

Why silence for unsandboxed

  • Most sessions are unsandboxed, so a permanent "unsandboxed" chip is a chip that's almost always saying nothing.
  • Marking the exception means the marker's presence is itself the information.
  • Matches how the rest of grove works — status dots appear for waiting sessions, not for idle ones.

What silence costs

  • Absence reads as "I didn't set it up", not "I chose this". For a session you deliberately ran unguarded, that's slightly wrong — but it was never the dangerous direction.
  • If grove later makes sandboxing the default, this inverts and the rule has to flip with it.
The gap

The grid has its own header — and it's the view that needs this most

When you're running five agents in parallel, "which of these are contained?" is the question you actually have. ContentHeader doesn't exist in that view, so a header-only answer goes silent exactly where it matters.

Why the grid needs it more

  • Parallel agents are exactly the case where containment is a decision you made per session.
  • Two panes side by side, one contained and one not, is the comparison you're making.
  • It costs one element in a header that already holds four.

Consistency rule

If it appears in both places it must mean the same thing and look the same. One shared SandboxMark component, two densities: label in the header, icon in the grid. Anything else is two sources of truth drifting apart.

Open question

Does the downgrade need a permanent home?

Option 1 — banner once, then silent. No new field. sandboxed flips to false, the session becomes an ordinary unsandboxed session, and the record of what it used to be is gone. Cheapest, and the state file stays exactly as it is.

Option 2 — persist the downgrade. Keep sandboxed: true (the record of intent) and add a runtime sandboxLost flag, so the marker keeps showing as a persistent warning. Needs a new field on Session and a state-file bump. But "this was contained and now isn't" stays legible for the life of the session — which matters, because grove sessions run for days and nobody remembers last Tuesday's banner.

My read: Option 1, unless you expect sessions to live long enough that you'd be surprised by one. The cost of 2 is a permanent warning on something that's already been dealt with, which is its own kind of noise. But 2 is the honest one, and honesty is the whole point of the field existing.

Two smaller things worth settling at the same time

New icon. IconName in ui/Icon.tsx:3 has 29 glyphs and none of them is a shield or a container. This needs a new one — and it should read as containment, not as safety, since ADR 0036 is filesystem-only.

Tooltip wording. The marker's label is "Sandboxed", which is a claim. The tooltip should be the qualified version — "Runs in a Linux VM. Your filesystem outside its worktree isn't visible. Network is unrestricted." — because that's what ADR 0036 actually bought, and it's the sentence every external tool puts in the risk tier's own help text.
