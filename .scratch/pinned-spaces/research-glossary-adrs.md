# Research: glossary, ADRs and pending work for pinned spaces

Sources read: GLOSSARY.md, docs/adr/0001-0006, AGENTS.md, docs/agents/*.md, .scratch/sidebar-branch-graph/*, .scratch/persisted-prefs/decision-log.md, .scratch/pinned-spaces/*.

## Glossary terms that constrain the feature
- **Space** (GLOSSARY.md:8-12): a folder; a worktree space is a space on a linked checkout. So "pin a worktree space" needs no extra rule; pinning is on spaces, never tabs (matches pinned-spaces decision-log 1).
- **Heading** (GLOSSARY.md:13-19, ADR 0005): a grouping, not a space; no tabs; click only folds. The Pinned group must NOT be called a heading, and must not be foldable-by-heading rules by accident. A Pinned group is a second, different grouping. Needs a word (see gaps).
- **Most urgent state** (GLOSSARY.md:20-22): order needs-you, finished, working, unknown, idle; a folded heading shows it for its spaces, an unfolded heading shows none. A Pinned group row is a space row, so it shows the space's own state as any row does. If the Pinned group is foldable, whether a folded group shows a roll-up is undecided (the glossary only says headings do).
- **Recent order** (GLOSSARY.md:37-39): tabs most recently shown first, per space and per window; Go to lists "tabs and spaces in the window's order". Tension: the brief says Go to lists pinned first. Pinned first then overrides Recent order for the top block. Within pinned, order is undecided (sidebar order? pin time? Recent order?). Note "Recent order" is per window; a pin is shared across windows, so pinned order must not depend on per-window Recent order if every window must look the same.
- **Active space** (GLOSSARY.md:34-36): "the main window shows if the active space is pinned" is this term. Brief wording is "the window you are working in"; decision-log item 3 flags the interpretation as unconfirmed.
- **Quiet space** (GLOSSARY.md:~75-81): a space that is not active, not under the active heading, has no working/needs-you/finished tab, and is not among the 5 most recently visited. Go to (empty query) and the sidebar spaces list fold quiet spaces behind "N quiet spaces". Conflict: a pinned space that is quiet. The brief says a pinned space "also stays in its place in the tree" and Go to lists pinned first, so pinned spaces must never be folded into the quiet fold in the Pinned group or in Go to; for the tree copy it is undecided (probably still quiet there, since pinning is "come back later" and quiet spaces are what you come back to). The quiet count "counts spaces": decide if a pinned space counts once. Also "a heading leaves the list only when all its spaces are quiet": a pin must not change that unless stated.
- **Go to** (GLOSSARY.md:~82-90): with empty query draws the sidebar's tree; with a query a flat ranked list of worktrees, then tabs; Enter on a worktree goes to the tab that decides its state. "Only navigates; runs no commands." So: pin/unpin cannot be done inside Go to (it would be a command) unless the glossary is amended; showing a pin mark there is fine. Empty-query Go to "draws the sidebar's tree", so a Pinned group on top would appear there too (consistent with "Go to lists pinned first"). With a query, "worktrees then tabs": pinned-first ordering among worktree hits is a new ranking rule.
- **Tab**, **Tab state**, **Needs-you reason**: unaffected. Opening a pinned space "works as any space: the tab that needs you, else last used" = Go to / row click rule (spec story 27-28, sidebar-branch-graph spec).
- **Grove CLI** (GLOSSARY.md): the CLI drives the app over the core socket. If pins live in core, a CLI way to list/pin is possible but not requested. Core owns spaces and tabs ("Core keeps spaces, tabs and state").

## ADRs
- ADR 0005 (sidebar groups a repo under a heading): Heading keyed by repo, fold saved per repo, defaults open; "The saved fold choices are a new stored preference that must drop repos that no longer exist." Direct precedent for "a pin vanishes when its space is closed" (drop saved entries whose subject is gone). It also says the heading is not a space and every git space sits under one. Tension: a pinned space appearing in a Pinned group AND in its repo heading means one space has two rows. ADR 0005 and the sidebar spec assume one row per space (spec story 41 says two spaces on one folder stay separate rows; Cmd+digit numbering "counts every row"). Duplicated rows break "number every row": Cmd+1..9 numbering must be defined to count each space once (in tree order, or pinned first). Also ADR 0005 rejects "main checkout as parent row", irrelevant here; the Pinned group is not a parent either. The Pinned group is a second grouping on top of ADR 0005; consider whether it needs its own ADR (hard to reverse: yes if pins are stored in core and shared; surprising: duplicates).
- ADR 0001: git reads never run repo code; pins need no git reads. A pin on a worktree space whose worktree is removed vanishes via the space closing.
- ADR 0002 (session names not saved: "a saved copy could only go stale or compete"): a pin must not store derived data (tab names, states, repo name, branch); store only the space identity. Repo name on a pinned row should be derived.
- ADR 0003/0004: no record kept on disk, usage-history.json is deleted at start. Different domain; shows the repo's lean toward saving little. ADR 0004's rationale (rewriting large files) not relevant to a small pin list.
- ADR 0006: unrelated (voice), except the pattern that new things are stated in an ADR with Considered-and-rejected.
- No ADR decides how user preferences or state are persisted. No ADR covers "persisted preferences". The only decision is .scratch/persisted-prefs/decision-log.md, which is not an ADR and said "No ADR needed", and that covers only window-side browser storage: eight settings (theme, zoom, sound, agent appearance, sidebar hidden, view state, dock width/expanded, pane dim) via a shared key/default/validity mechanism over per-window `localStorage` (KeyValueStore getter, silent on failure; "a change holds until the window closes"). Heading fold (sidebar-branch-graph issue 03, ADR 0005) was to use the same approach, so it is also window-local.
  - Conflict with the pinned requirements: "same in every window" and "survive restarts" cannot be met by that window-local localStorage mechanism (each window has its own storage and a setting "holds until the window closes" if storage is blocked). Spaces and tabs are saved by the core (packages/core/spaces.ts: loadState/saveState, state file written only when the core accepts the change; core also has config/store.ts with atomicWrite and a validated config). So the natural home is core state beside spaces (a pin as part of the saved space record, which also makes "vanishes with its space" automatic), not the persisted-prefs mechanism. This is a real decision with no ADR yet; worth one (pins in core state, shared by all windows, versus window storage).
  - A possible spec-side note: `diffPrefs` in core state is per-folder saved state already (spaces.ts:331), a precedent for per-space data in core state.

## Interactions to resolve
- Cmd+1..9 / sidebar order: `sidebarSpaceOrder` (packages/ui/sidebar-model.ts:83-86; research-data-model.md:9) feeds both Go to and Cmd+digit numbering. Sidebar spec story 47 says numbers count every row including folded ones. With a Pinned group on top: number pinned first then the tree (each space once), or keep the tree order and ignore pins. Not decided. Changing numbering silently would move every existing shortcut once a space is pinned.
- Duplicate rows: the same space in Pinned and in the tree; row click, active-row highlight, and "the active space is the selected row" (research-glossary-adrs of the sidebar-branch-graph, item 6) need to highlight both or one.
- Folded heading force-open ("active space's heading stays open while active") is about the tree; the Pinned group copy makes the space reachable even when its heading is folded, so jump behaviour (spec story 36) still opens the heading; unchanged.
- Quiet fold (above). Also "keeps the usual sidebar order" (story 45): the Pinned group is an explicit exception to the sidebar order.
- Pinned row content: "same rows as the tree plus the repo name": heading name is the repo, which is derived (ADR 0002 spirit). A worktree row is named by space name, main row by rename/branch/folder; a Pinned row loses its heading context, hence repo name. Names must be unambiguous for two spaces of equal name.
- Window indicator: "main window shows if active space is pinned". Per-window glossary has no "main window"; the brief says "the window you are working in". Both use "window" for the Grove window; the term "main window" is not in the glossary.
- Pin vanishes when its space is closed: matches ADR 0005's "drop what no longer exists". A space re-added later is not pinned again (confirm). A worktree removed and recreated at the same path: identity question (folder path vs space id).

## Terms the glossary lacks (needed)
- **Pin / pinned space**: a space the human marked to come back to; kept in core, same in every window, gone when the space closes. Define as a mark on a space, not a space or tab.
- **Pinned group**: the group at the top of the sidebar (and Go to's empty-query tree) listing pinned spaces. State it is a grouping like a Heading but is not one (Heading is defined as a repo's group), and that a pinned space also stays in its repo heading.
- **Unpin** (or toggle pin) and the key action name for the shortcut; the shortcut is a rebindable key action (KEY_ACTIONS in packages/core/config/schema.ts) like the push-to-talk key.
- Pin indicator / pin mark (the mark in the row and in the main window's display of the active space).
- "Main window": not a glossary term; use Active space / the window.
- Amend: Recent order (Go to lists pinned first, then Recent order), Quiet space (pinned never quiet, or not), Go to (pinned first; still only navigates), Space (can be pinned). Update Most urgent state only if the Pinned group can fold.

## Verdict
No ADR forbids the feature. Real constraints: (1) glossary says a heading is a grouping, not a space, and one row per space is assumed everywhere; the Pinned group duplicates a row, affecting Cmd+digit numbering, the active-row highlight and the quiet count; (2) Go to "only navigates", so no pin toggle there; (3) persistence: the persisted-prefs approach is per-window browser storage and cannot give "same in every window", so pins should live in core state with the spaces; no ADR decides persistence yet, so a short ADR is warranted (pins held by core, keyed to the space, removed with the space).
